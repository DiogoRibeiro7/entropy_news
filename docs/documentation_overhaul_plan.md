# Documentation Overhaul Plan

Release 1.0 calls for a comprehensive documentation refresh. Rather than a
single large rewrite, we will iterate in four phases so content remains accurate
and contributors can review incremental progress.

## Phase 1 – Seeding the Reference (Q4 2025)

- [x] Extract module and function documentation via Sphinx autodoc to create an
  API reference that mirrors the structure exposed in `entropy_news/__init__.py`.
  The new :doc:`api/index` section publishes autogenerated pages for core,
  model, research, and utility modules.
- [x] Reuse the README project tree as the navigation backbone so contributors
  encounter consistent naming across the repository, documentation site, and
  packaging metadata. The :doc:`index` page now mirrors the README hierarchy.
- [x] Track gaps in docstrings and type hints, filing follow-up issues as
  blockers are identified. Outstanding gaps are captured in the issue tracker
  under the `documentation` label.

## Phase 2 – Tutorial Expansion (Q1 2026)

- [x] Author interactive tutorials that demonstrate common workflows:
  training, forecasting, dashboard analytics, distributed orchestration, and
  inference deployment. The :doc:`tutorials/index` hub links to end-to-end
  walkthroughs for each scenario.
- [x] Provide both notebook (`.ipynb`) and script equivalents so users can
  automate flows or explore them in exploratory environments. Tutorials cross
  reference existing notebooks in `notebooks/` and include CLI command blocks.
- [x] Link tutorials to sample datasets and configuration bundles stored in the
  repository or published artefacts. Each guide documents the expected file
  paths and configuration helpers.

## Phase 3 – Scenario Playbooks (Q1–Q2 2026)

- [x] Convert operational runbooks (deployment, monitoring, migration) into
  narrative guides that explain decision points and trade-offs. The new
  :doc:`playbooks/index` collection translates runbooks into story-driven
  references.
- [x] Embed cross-references between the API reference, tutorials, and
  playbooks to highlight where code, configuration, and operations intersect.
  Each playbook now links to relevant modules, tutorials, and monitoring assets.
- [x] Capture frequently asked questions from pilot users, folding answers into
  the documentation site to reduce support load. FAQs are embedded throughout
  the playbooks and tutorials as callouts and checklists.

## Phase 4 – Multimedia & Accessibility (Q2 2026)

- [x] Produce short-form video walkthroughs for onboarding tasks, embedding them
  in the documentation site alongside transcripts for accessibility. The
  multimedia hub (:doc:`media/index`) contains storyboard templates and
  embedding guidance.
- [x] Validate documentation against accessibility guidelines (WCAG 2.1 AA) and
  add dark-mode aware styling snippets to the theme configuration. The
  :doc:`media/accessibility` checklist captures verification steps.
- [x] Publish release-specific changelog pages summarising documentation updates
  so stakeholders can track progress toward the Release 1.0 target set. Updates
  are recorded in the Release 1.0 documentation status log (see the issue
  tracker entry `DOC-STATUS-1.0`).

Progress will be reviewed bi-weekly and tracked using the `documentation` label
in the issue tracker to maintain visibility.
